WHY STEWARD

Housekeeping should be observable, repeatable, and boring.

Steward focuses on evidence-backed repository health instead of pretending every cleanup task needs artificial intelligence or destructive automation.

01

Deterministic scans

The same repository state should produce the same useful finding. Stable fingerprints make issues trackable across changes.

02

Explainable findings

Every result tells you what was found, where it was found, how confident Steward is, and what remediation makes sense.

03

Safe remediation

Scanning never writes. Fixes require explicit --safe, and dry runs never mutate your repository.

04

Evidence you can use

Human reports, JSON output, health deltas, CI decisions, and FORGE evidence all share the same core scan contract.

THE MODEL

Observe → explain → decide → maintain.

Steward keeps ordinary repository facts deterministic and leaves architecture decisions, product judgment, and orchestration to the systems that own those jobs.

01

Scan

steward scan .

Collect repository facts, apply versioned rule packs, and produce stable findings.

02

Understand

steward doctor .

See health, severity counts, categories, and the issues that deserve attention.

03

Remediate

steward fix --safe

Apply only findings with an explicit deterministic safe-fix capability.

04

Prove

steward report --output ...

Persist JSON reports, compare health over time, or export evidence for other systems.

INSTALL

Install globally from npm

npm install -g @godtech/steward@0.1.1

Scan a repository

steward scan .
steward doctor .
steward scan . --json

Install globally from npm

npm.cmd install -g @godtech/steward@0.1.1
PowerShell execution policy

If PowerShell blocks the generated steward.ps1 shim, use the command shim directly:

steward.cmd --version
steward.cmd scan .

TRUSTED EXTERNAL PACKS

Verification first. Execution never implied.

The published 0.1.1 release establishes signed pack verification and the versioned external rule API. Current source also contains post-release bounded WASM runtime hardening from PR #37. Normal scans and the GitHub Action still do not automatically execute third-party packs.

VERIFY

Identity + integrity

Manifest compatibility, allow policy, publisher trust, SHA-256 artifact verification, Ed25519 signatures, and WASM validation.

ISOLATE

Bounded runtime

Source-level runtime hardening includes worker isolation, explicit memory ceilings, timeouts, pointer validation, and output limits.

GOVERN

Fail closed

Execution remains separate from verification. Governance and audit gates must be satisfied before any future opt-in execution surface is considered.

SAFETY MODEL

Observe first. Explain second. Modify only when explicitly safe.

Steward does not delete uncertain files, mutate the repository during scanning, expose credentials in findings, or execute arbitrary external JavaScript rule packages.
