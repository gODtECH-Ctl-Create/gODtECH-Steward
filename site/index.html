WHY STEWARD

Housekeeping should be observable, repeatable, and boring.

Steward focuses on evidence-backed repository health instead of pretending every cleanup task needs artificial intelligence (AI) or destructive automation.

01

Deterministic scans

The same repository state should produce the same useful finding. Stable fingerprints make issues trackable across changes.

02

Explainable findings

Every result tells you what was found, where it was found, how confident Steward is, and what remediation makes sense.

03

Safe remediation

Scanning never writes. Fixes require explicit --safe, and dry runs never mutate your repository.

04

Evidence you can use

Human reports, JSON output, health deltas, Continuous Integration (CI) decisions, and FORGE evidence all share the same core scan contract.

THE MODEL

Observe → explain → decide → maintain.

Steward keeps ordinary repository facts deterministic and leaves architecture decisions, product judgment, and orchestration to the systems that own those jobs.

01

Scan

steward scan .

Collect repository facts, apply versioned rule packs, and produce stable findings.

02

Understand

steward doctor .

See health, severity counts, categories, and the issues that deserve attention.

03

Remediate

steward fix --safe

Apply only findings with an explicit deterministic safe-fix capability.

04

Prove

steward report --output ...

Persist JSON reports, compare health over time, or export evidence for other systems.

WHAT STEWARD CHECKS

One scanner. Several kinds of repository health.

REPOSITORY

Repository hygiene

README, ignore files, large files, tracked disposable outputs, generated artifacts.

SECURITY

Credential signals

Tracked environment files and high-confidence secret-like patterns without exposing secret values.

DOCS

Documentation integrity

Broken or malformed local Markdown links and other documentation consistency issues.

DEPENDENCIES

Dependency hygiene

Package-manager metadata and lockfile consistency, including conflicting lockfiles.

MAINTENANCE

Maintenance drift

Merge-conflict markers, TODO/FIXME maintenance signals, and stale development artifacts.

METADATA

Project identity

Package identity, descriptions, and publishable metadata where the repository exposes them.

INSTALL

One package. One command.

Steward 0.1.0 is published to npm as @godtech/steward. The GitHub release also carries the package tarball, checksum file, and Software Bill of Materials (SBOM).

Install globally from npm

npm install -g @godtech/steward@0.1.0

Scan a repository

steward scan .
steward doctor .
steward scan . --json

Install globally from npm

npm.cmd install -g @godtech/steward@0.1.0
PowerShell execution policy

PowerShell may block the generated steward.ps1 shim. You can invoke the Windows command shim directly:

steward.cmd --version
steward.cmd scan .

SAFETY MODEL

Observe first. Explain second. Modify only when explicitly safe.

Steward does not delete uncertain files, mutate the repository during scanning, expose credentials in findings, or execute arbitrary external JavaScript rule packages.

01Scanning is read-only.
02--safe is required for remediation.
03--dry-run never writes.
04Security findings are observation-only.
05External rule packs are opt-in and verification-first.
